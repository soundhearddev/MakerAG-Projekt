http REQUESTS

HTTP Requests sind Anfragen, die ein Client (z. B. ein Browser oder ein Programm) an einen Webserver sendet, um Daten zu bekommen oder zu senden.

Jede Website basiert im Hintergrund auf solchen Requests.

Was passiert bei einem HTTP Request?

Wenn du eine Website öffnest:

  1. Dein Browser schickt eine Anfrage an den Server
  2. Der Server verarbeitet die Anfrage
  3. Der Server schickt eine Antwort zurück
  4. Dein Browser zeigt die Daten an

Aufbau eines HTTP Requests

Ein Request besteht meistens aus:

  • Methode (Was soll passieren?)
  • URL (Wohin geht die Anfrage?)
  • Header (Zusatzinfos wie Browser, Sprache, etc.)
  • Body (Daten, die gesendet werden)

Wichtige HTTP Methoden

GET

GET /users HTTP/1.1

→ Daten abrufen (z. B. Website laden)

POST

POST /login HTTP/1.1

→ Daten senden (z. B. Login-Formular)

PUT

→ Daten aktualisieren

DELETE

→ Daten löschen

Beispiel aus dem Alltag

Du öffnest eine Website:

  • Browser → GET /index.html
  • Server → sendet HTML zurück

Du klickst „Senden“ in einem Formular:

  • Browser → POST /feedback
  • Server → speichert Daten in der Datenbank

HTTP Response (Antwort)

Der Server antwortet immer mit:

  • Status Code
  • Daten (HTML, JSON, etc.)

Beispiele:

  • 200 OK → alles gut
  • 404 Not Found → Seite nicht gefunden
  • 500 Server Error → Fehler im Backend

Technisch betrachtet

HTTP ist zustandslos:

Das heißt:

  • jeder Request ist unabhängig
  • der Server „merkt“ sich nichts automatisch

Wenn man Zustand braucht (z. B. Login), nutzt man:

  • Sessions
  • Cookies
  • Tokens

Umsetzung in diesem Projekt

In diesem Projekt werden HTTP Requests genutzt, um zwischen Frontend und Backend zu kommunizieren. Das Frontend sendet Requests (z. B. über JavaScript) an PHP-Skripte, welche wiederum Daten aus der MariaDB-Datenbank holen und als Antwort zurückgeben.
